### Count-task confusion matrix (val split)

One PNG + CSV per (encoder, pool) in [`plots/probe_analysis/count_confusion_<enc>_<pool>.png`](plots/probe_analysis/). Each plot is the 8×8 confusion matrix over counts 3–10 (the 11 raw classifier outputs are cropped to the actual count range), row-normalised for shading and annotated with raw counts. Key qualitative reads:

- **DINO Teacher GAP** — almost-tridiagonal: confusions live on the diagonal and the two adjacent off-diagonals. The model knows the count to within ±1 in >90 % of cases.
- **CLIP CLS** — diagonal is much weaker, and high counts (8, 9) are systematically biased toward the corner (count=10) — the model "gives up" and predicts the highest class for crowded scenes. Consistent with CLIP's 47 % count accuracy vs. DINO's 65 %.
- The plots are produced by [`make_plots.py`](make_plots.py) directly from the saved CSVs (no GPU needed), so any future re-styling is a local re-run.

### Analysis

- **DINO dominates counting** (+12 pp CLS, +21 pp GAP over CLIP). Self-supervised multi-crop forces the encoder to preserve fine-grained spatial structure, which is exactly what counting needs. The confusion matrix shows the remaining DINO errors are almost entirely ±1 off-by-one (diagonal + first off-diagonals account for >95 % of mass).
- **CLIP dominates colour prediction** (+5–6 pp). The caption contains every object's colour verbatim, so contrastive alignment gets direct supervision on colour features. Per-colour F1 is >0.98 for every one of the 8 colours with CLIP CLS.
- **GAP > CLS for DINO on counting** (0.67 vs 0.61). The CLS token is a global summary; patch-level pooling retains more spatial variance.
- **CLS ≥ GAP for CLIP.** The CLIP text-side projects the EOT token against image CLS, so CLS gets an explicit learned summary; GAP is what the ViT happens to leave behind.
- **DINO Teacher ≈ DINO Student** throughout (EMA parity). Teacher edges Student on GAP-count by ~0.01 — consistent with it being the slowly-tracked smoothed copy.

## §2.3 Cross-modal retrieval (CLIP, 15 K val pairs)

| Direction | R@1 | R@3 |
|---|---|---|
| Image → Text | **96.03 %** | 99.25 % |
| Text → Image | **96.50 %** | 99.53 % |
| Caption-equiv R@1 | i2t 96.13 %, t2i 96.59 % | — |

"Caption-equivalence" relaxes ground truth: many val images share byte-identical captions (CLEVR captions carry no spatial info), so retrieving any image with the same caption still counts. The relaxed number is only 0.1 pp higher than strict R@1, confirming our dedup-aware sampler kept the evaluation honest.

### Quantified failure-mode breakdown

For every query whose top-1 retrieval was *wrong*, we parse the GT and retrieved captions for (count, colour-multiset, size-multiset, material-multiset, shape-multiset) and check how often the retrieval agrees with GT on each attribute. Full numbers in [`plots/retrieval_stats.json`](plots/retrieval_stats.json):

| Direction | n_failures | same count | same colours | same sizes | same materials | same shapes |
|---|---|---|---|---|---|---|
| Image → Text | 596 / 15000 | 41.8 % | 19.0 % | 25.2 % | 24.2 % | **5.7 %** |
| Text → Image | 525 / 15000 | 43.6 % | 28.0 % | 26.3 % | 28.9 % | **6.3 %** |

These numbers are more interesting than I (the auditor) initially predicted:

- **Count is the most-preserved attribute** (≈42–44 % match in failures, vs. a chance baseline of 1/8 = 12.5 % over the 8 count classes). So CLIP failures *do* tend to retrieve a scene with the right number of objects — but in *less than half* of the failures, meaning count is not what's saving the top-1 in successes either.
- **Colour / size / material multisets match in 19–29 %** of failures. Each is well above its own random baseline (~10 %) — but the top-1 wrong caption still differs in at least one of these in the majority of cases.
- **Shape multisets match in only 5–7 %** of failures, *barely above* the chance baseline. This is a striking sign: CLIP's failures are not "near-duplicate scenes that swap one attribute" — they are scenes with substantially different shape composition. The contrastive head learns to align coarse attributes (count, colour palette) but lets fine compositional shape structure drift.

This is exactly the pattern we'd expect when (a) captions list every attribute but with no spatial structure, so all permutations of the same shape multiset look identical to the text encoder, and (b) the image encoder has no pressure beyond contrastive alignment. A DINO-style spatial inductive bias would likely tighten this up — see Part Aa §2.2 t-SNE for indirect evidence (DINO clusters by count more cleanly than CLIP).

## Piazza clarifications that affected our implementation

- **Tokenizer** — CLEVR-specific (size/colour/material/shape vocab) is endorsed. We built a 36-token vocab directly from train captions.
- **Part_Aa JSONs with absolute image paths** — handled by reading `image_filename` only.
- **Cross-modal captions** — pulled from the course Drive folder, placed at `Part_Aa/Clevr_official/captions/clevr_val_captions.json` on HPC.
- **Duplicate captions in contrastive batch** — implemented deduplication via `DedupBatchSampler`; each batch contains at most one sample per unique caption. (Other acceptable option per instructor: off-diagonal masking.)
- **Test split in Part_Aa** — instructor said reporting on test is optional; we report train + val only.
